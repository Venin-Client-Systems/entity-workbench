# Bounded current citation metadata

`Workspace::page_citation_catalogue` and `Workspace::read_citation_selections` share one metadata projection for finding citations. Command schema v17 exposes them as `page_citation_catalogue` and `read_citation_selections`, each with a typed request and `expected_revision`. Four v1 request/response schemas describe their dedicated responses; they return the same projection through both full and presentation dispatch modes. UI adoption is separate. Existing finding, report, identity and source-inspection writers are unchanged. The default workspace response still contains its transaction array.

## Supported records and exact fields

Supported kinds are observations, transactions and whole evidence. The fixed order is observation, transaction, evidence, followed by ascending canonical insertion sequence within each kind. This preserves the existing picker order. The selected reader returns the exact requested set in that same order, regardless of request order; consumers reviewing a saved finding map the rows into its separately persisted supporting/contradicting ID order.

| Kind | Returned fields |
| --- | --- |
| Observation | ID, entity ID, current entity name or null, field, value, review state, complete typed anchor, source metadata |
| Transaction | ID, description, amount, currency, transaction date, account, review state, version, complete typed anchor, source metadata |
| Whole evidence | ID and source metadata; no invented review state or anchor |
| Source metadata | ID, name, SHA-256, byte length, media type, origin group, import timestamp, extraction status |

Evidence text and acquisition arrays, duplicate/transfer arrays, entity identifier arrays and prior report HTML are not copied into these projections. Amount/date validation reuses the existing exact decimal and canonical-date helpers. The reader does not aggregate money, convert currencies, hide duplicate/transfer records or independently validate financial fields omitted from the projection. Returned strings are not normalized or truncated. Text remains untrusted and must be rendered inertly.

A missing entity permits the existing entity-ID label fallback. Missing source evidence, mismatched canonical/body identity, an invalid source digest, ambiguous supported-kind IDs and malformed required projected fields fail explicitly. Referenced evidence must satisfy canonical key = body ID = SHA-256; A's metadata cannot retarget its digest/size to a different intact original B. A collision with another *citable* kind is an error; unrelated kinds are not added to citation resolution.

These are metadata reads. They do not rehash originals, accept extraction results, validate anchor positions against source content, or establish source independence. A typed page/message/capture anchor can be represented without claiming that current source-review operations support it. Whole evidence remains discoverable regardless of its extraction status, including unprocessed or acquisition-only records. All observation/transaction review states remain visible.

## Requests, matching and continuation

A catalogue request contains `query`, `excluded_ids`, `page_size` and optional `cursor`. Query text is at most 256 UTF-8 bytes; whitespace and punctuation are literal. Exclusions contain 0–100 unique opaque IDs; page size is 1–50; a cursor is nonempty and at most 2,048 bytes. IDs contain 1–256 bytes without controls. Unknown request fields are rejected. The selected request contains 1–100 unique IDs and does not silently discard missing/unsupported entries.

Catalogue matching uses the shared `literal_search` helper: locale-independent Rust whole-string lowercase followed by literal substring containment. The response reports `unicode_default_lowercase_literal_v1` and the running Rust Unicode version. No SQL pattern, regex, normalization, tokenization or case-insensitive collation is substituted. As documented in [transaction literal search](../transactions/LITERAL-SEARCH.md), a browser with a different Unicode version can differ for newly assigned characters; the reported Rust algorithm is authoritative.

The complete searchable string preserves the previous picker content: observation entity label/field/value plus `Observation`, review and source name; transaction description/amount/currency plus `Transaction`, date, `account`, account value, review and source name; whole-source name plus `Whole source`, extraction status and source name. Case mapping occurs after concatenation, retaining contextual Unicode mappings. Query case mapping occurs once. Empty query includes every non-excluded supported record. Exclusion order has set semantics.

The catalogue response contains schema version 1, pinned workspace revision, matching profile, query digest, `scope_count`, rows and optional continuation. Count means query matches after exclusions and before paging; it is not an accepted-evidence count. Cursors bind revision, lowered query, matching profile, exclusion set, page size and the fixed kind/sequence order. Their positions must identify a matching non-excluded record. They provide continuation consistency, not authenticated access control.

## Size, snapshot and failure boundaries

The per-entry and aggregate returned projection budget is 2 MiB. SQLite computes projected lengths before Rust copies/deserializes their text. A catalogue page may be shorter than its requested row count when its aggregate byte budget is reached. Its cursor follows the last returned entry, leaving the next entry eligible; no entry is silently dropped. An individually oversized projection fails explicitly. The selected reader preflights the *entire selected set's* projected lengths before decoding any selected body and rejects aggregate overflow without a partial result.

Catalogue search streams projected candidates through Rust to calculate the complete denominator, retaining only the requested page. It decodes and validates every non-excluded projected candidate, including candidates outside the returned page or not matching the query. Every such candidate must fit the per-entry 2 MiB bound; a corrupt or oversized candidate fails the whole query instead of being concealed by search or pagination. This is not an indexed search or an assurance of two-second performance. SQLite still reads/parses underlying retained JSON, including omitted source blobs, and may use its own query buffers. Its projection, identity-count and ordering work is not bounded by the returned page size. Search concatenation, lowercasing, deserialization and the response envelope have additional allocations. The projection budget is not a process-wide memory quota or an exact wire-byte ceiling.

Revision, selected metadata, counts and row decoding share one SQLite read transaction. A stale expected revision fails; a concurrent canonical writer cannot substitute a newer source label, row or count into the old response. Failures roll back the read snapshot, create no event and do not change canonical history, originals or report bytes. A consumer retains the selected IDs and roles after failure, reports unavailable selection details and does not substitute an empty successful selection.

## Review, source groups and reports remain separate

Finding drafts may cite any review state; existing `review_finding` still requires accepted observations and transactions on both citation roles, supported anchors and verified distinct originals. Citation role is not a record's own review state. Origin groups remain literal evidence metadata: multiple citations of the same original share a group, while differing groups do not prove independent sources. Count groups only after the complete selected set resolves, and identify missing/empty legacy group values rather than presenting them as established independence.

Current findings retain IDs rather than pinned historical record versions. These readers resolve the current records at the explicit workspace revision. Current corrections continue to reopen review through existing writers. Previously saved HTML snapshots remain immutable and are retrieved with their retained digest; never regenerate a previous export from this catalogue.

The existing source-viewer UI still consumes full `Evidence.text`. Migrating citation selection removes its dependence on a full transaction array, not that separate evidence-text dependency. Source inspection's returned revision describes its own snapshot: an expected-revision input and bounded whole-source text paging remain separate work. Original rehash and source-content integrity checks remain the responsibility of source inspection; this metadata slice does not substitute for that read.

## Verification scope

Focused synthetic Rust regressions cover mixed-kind multi-page order, maximum selected sets, all represented review states, Unicode/literal/whitespace matching, query and exclusion denominators, selected-set ordering, omitted large source text, atomic projected preflight, byte-short pages, individual overflow, missing/colliding/corrupt identities and fields, A/B evidence retargeting, hostile bounds/cursors, stale revisions, origin-group preservation, unsupported anchor representation, unchanged report/original bytes, and two actual canonical writers interleaved inside a snapshot. The final ordinary core suite passed 228 tests, including all 10 citation groups; 21 native-engine tests remained explicitly ignored by that ordinary run. Strict Clippy passed in debug and release modes, formatting passed, and the staged public audit passed for all six changed files. The first focused attempt passed 9/10: its concurrent-writer fixture enabled WAL before opening a second workspace, whose initialization resets journal mode. Opening both connections before enabling WAL repaired the fixture; the final tests retain actual interleaved writes and prove that selected review state remains from the original read snapshot. No production concurrency rule or test assertion was weakened. No visual/Figma, native distribution, indexed-performance or complete-release gate is claimed.

The integrated v17 command slice passed 233 ordinary core tests with 21 native-engine tests explicitly ignored, strict all-target Clippy and formatting. Its public-dispatch regression verifies identical dedicated responses through both existing response modes, exact selected-set resolution and unchanged canonical records. All 57 earlier schema files remained byte-identical; v17 preserves all 50 v16 command variants and 29 definitions and adds two commands. No UI or desktop transport mode changed. Retained logs: `artifacts/citation-integrated-core.log`, `artifacts/citation-integrated-clippy.log`.
