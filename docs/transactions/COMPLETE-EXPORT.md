# Complete filtered transaction JSON export

`Workspace::export_transactions` is an explicit backend export for the entire requested scope. It is separate from the visible ledger page. The current slice has no command/schema/UI wiring; it does not change the desktop's existing download action.

Its request contains the same exact date/account/currency/review filters and date order as transaction paging, plus the same bounded literal description/account/date query. It has no cursor or page size. Scope predicates, complete-string Unicode lowercase matching and query bounds reuse the existing domain helpers. Whitespace and wildcard-looking punctuation stay literal; decimal strings, original descriptions, source anchors, review states, duplicate candidates and transfer links remain canonical values. No record is silently deduplicated or converted to another currency. A stable date sort retains canonical insertion order for ties in both directions.

The response identifies the workspace revision, full request, matching profile, export query digest, complete row count, exact UTF-8 JSON byte count and SHA-256. Its `json` field is a pretty-printed array of every selected canonical transaction. A successful empty selection is exactly `[]`; a failed or oversized export produces an error rather than a shorter array. Its digest identifies an export scope, distinct from a page digest that also binds page size.

Revision, ordered transaction reads and source metadata share one SQLite snapshot. Canonical key/body identities and versions are checked. The existing transaction validator runs on every row, including rows outside the selection: malformed retained data fails explicitly. Nonempty literal matching validates scoped text before review selection, as the search reader does. Every distinct original referenced by selected rows is verified once, with canonical evidence key = body ID = SHA-256. Missing, substituted or changed selected originals fail the whole export. This does not accept pending observations or validate document anchors; source review retains those responsibilities.

The complete inner JSON array has a 256 MiB limit enforced by a capped serializer. The outer response envelope, JSON string escaping, selected transaction objects, per-row decoding, original verification and serializer capacity have additional allocations. This is not a total-memory or execution-time bound. The reader retains all selected rows and sorts them in memory, and SQLite scans canonical JSON; it is not a streaming-file export or an indexed performance claim. This work removes the need to retain every transaction in the interface merely to preserve full export. It must only run after an explicit analyst export action; no background refresh should request it.

All earlier report snapshots, canonical records and originals remain unchanged. A caller must bind the result to the requested revision/scope, present the complete row count, and await the existing native download completion/error path. It must not substitute a current page or report that a file was saved merely because this reader returned. A subsequent workspace correction does not alter already exported bytes; the embedded response metadata describes the captured revision.

Synthetic verification compares all exported rows to concatenated real search pages across filters and both date orders, including a 305-row case, exact eight-place amounts, source markup and equal-date ties. Tests also cover exact serializer boundaries, successful empty arrays, malformed and stale requests, hidden corrupt/nonmatching records, missing/substituted originals, preserved report bytes and an actual concurrent correction after revision capture.

The backend slice passed six focused regressions, the full 253 ordinary core tests (21 native-engine cases explicitly ignored), strict all-target Clippy and formatting. The integrated payload diagnostic also passed its Rust serializer test and two Python failure-history tests without rerunning the retained 100,000-row measurement. Logs: `artifacts/transaction-export-{focused,core,clippy}.log`.
