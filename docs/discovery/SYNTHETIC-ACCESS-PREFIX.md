# Private synthetic publisher access prefix

This source-only increment exercises an access-prefix transaction sequence through the real canonical SQLite store and retained originals. It uses the opaque `selected-publisher-access-v1` plan. It does not implement a public command, production claimant, coordinator adapter, network executor, benchmark campaign or user interface. Normal native collection remains disabled. The only queue method is compiled under `cfg(test)`; the private types are not public exports.

The profile is specific to the frozen benchmark metadata. Its embedded publisher/seed/query bindings grant no permission to fetch a website. The proposed interpretation of the frozen seed as the first **content** request still needs a benchmark design clarification; this increment does not amend the frozen initial-request rule. No public URLs are fetched by these tests. Access decisions, bodies, resolver observations and ownership transitions are synthetic fixtures, not actual publisher permission or independent relevance labels.

## Namespace and admission

Experimental runs use `collection_access_experiment_v5` and their request-key map uses `collection_access_experiment_key_v5`. They are not stored as `collection_run`, so v1–v4 catalogues and ordinary startup/recovery do not deserialize or claim them. There is no storage migration, public schema or change to historical record encodings. The new private format rejects unknown fields, including empty tagged seed/reserved objects. Its local progress decoder admits only reserved, observed and interrupted-unknown states; it does not change the legacy decoder or invent non-lossless settlements. A normal coordinator leaves the experimental rows unchanged; it does not recover or execute them.

Only an otherwise empty canonical workspace at revision zero may admit a new fixture. Admission checks a canonical UUID request key and the validated profile. An exact key retry returns the matching existing record after full replay, including under still-held publication-only quarantine. Another key/input or a foreign corpus fails closed. Every later read requires exactly this run, its key mapping and its receipt-derived Evidence records; unexpected canonical rows, existing text or changed acquisitions are refused. No shared text is cleared to create a cold corpus. This deliberately excludes ordinary mixed workspaces and cannot serve as general corpus admission.

## Prefix, requests and decision

The run starts with one fixed first-start/deadline pair and one ownership lease. Each reservation is committed before a request ticket is returned. The shared request counter covers derived robots, every explicitly selected access URL and the exact first content seed; zero/lower quotas and the total ceiling of 50 apply to all phases. Charged failures and unresolved reservations are never refunded or automatically retried. No transport is called by the store.

The ordered prefix is:

1. The exact seed host's `/robots.txt`.
2. Explicit access URLs in analyst-selected order, preceded by that exact host's robots acquisition when it has not already occurred. A selected URL equal to an already acquired robots URL binds that acquisition instead of making another request only when it is a complete identity-encoded 200 document; a robots 404 can permit a path but does not satisfy this explicit selected-document prerequisite.
3. `AwaitingDecision`, with no lease and no content interpretation, promotion or frontier. The method returns; no workspace mutex is retained while an analyst would wait.
4. An explicit `Allow`, `Deny` or `Unknown` decision. Only `Allow` can produce `ReadyContent`.
5. An explicit new start/resume using a new lease and incremented generation, retaining the original deadline and charge count. It may reserve only the exact frozen seed.
6. Settlement at `ContentBoundary`, or a typed failed/blocked/quota/cancelled/recovery-required outcome. This implementation stops there; it never follows parsed links or redirects and is not a second crawler.

Robots uses the existing conservative UTF-8/512,000-byte parser, 404 rule, path permission and crawl-delay refusal. Each host has its own prerequisite; a sibling host's rules cannot authorize it. Encoded responses, unsupported robots and HTTP refusals remain failures, with complete acquired bodies retained. Selected access requires a complete, identity-encoded HTTP 200 response but does not assert the document contains terms, grants permission, is current or was understood. The decision is a caller's explicit fixture assertion. Denial/unknown/expiry cannot reserve content.

The decision hash binds the run/generation, plan hash, entire pre-decision journal/checkpoint, original first deadline, request count and ordered receipt inventory. Each inventory entry binds URL, purpose/selected index, exact raw receipt digest, original hash/length and raw observed wall sample. Its private encoding is compact struct-order JSON with the review digest field empty. Publication also requires the sampled workspace revision. Exact decision retries after acknowledgement loss return the current record without another write or request; a different decision/key/hash is refused.

## Receipts, purpose and global Evidence

The prefix reuses the existing lossless transport receipt. Synthetic-only candidate observations are required. Complete bytes are hashed and validated; stopped outcomes cannot invent a body. Raw response head, identity encoding, phase, delivery uncertainty, elapsed sample, raw wall time, complete-plus-stop race, resolver uncertainty and local-quiescence result remain in the journal. Unknown quiescence quarantines the bound ownership lifetime before fallible bounds, replay or receipt interpretation, even if the supplied receipt then fails validation; publication-only ownership can retry the same receipt, but cannot admit another request. An unacknowledged committed receipt can be inspected and exactly replayed without adding an acquisition or revision.

Existing shared retention creates inert originals by digest and appends the ordinary acquisition identity. The experimental journal separately binds acquisition purpose, sequence, run, generation and lease. Access receipts have no content parent, text promotion or discovery credit. The bounded static parser is used only for an independently allowed seed response; extracted links are discarded at the explicit continuation boundary. Unsupported/incomplete/stopped content is never promoted. Complete acquired originals survive derivative refusal, subject to the existing metadata publication bound.

A byte-identical access and later content response legitimately share one global Evidence identity. After the later content acquisition, that Evidence may contain text, while the earlier request remains access-purpose and never becomes a content ancestor. This is tested explicitly. General activation requires acquisition-scoped corpus selection and positive content admission: content hash or the presence of global `Evidence.text` alone is not enough. Normal Search has no support for the private experimental namespace, and this increment creates no new Search eligibility contract.

## Ownership, recovery and rollback

Execution tickets bind run, generation, unique lease and the exact ownership lifetime. Reservation tickets additionally bind request sequence/URL/purpose and plan hash. A released or replacement owner cannot settle an old ticket. An ownership-quarantined guard can publish only while the original descriptor/lifetime is still held. The store checks executable versus publication ownership separately and performs revision-checked canonical transactions.

Canonical cancellation precedes any later receipt interpretation. A complete-body cancellation race retains bytes and the receipt without text promotion. Fresh event timestamps obey the existing strict live-time rules. The narrow owned stop operation has no caller-supplied time and uses only the validated reservation checkpoint; it preserves settlement after a backward clock jump. Raw backward receipt time is not clamped, and the existing unknown/clock/cancel/quota precedence is shared.

Exclusive recovery marks a charged unresolved request `InterruptedUnknown`, drops the lease and refuses continuation from that reservation. It does not assert that a response was received or that a prior provider stopped. Recovery after an already complete settled request may resume the remaining prefix with a new lease/generation; no old lease crosses the analyst decision boundary. Backup/restore copies the private records and all canonical Evidence originals through existing recovery, without inventing a normal collection claimant.

A failed checkpoint or derivative publication rolls back revision, events, run and Evidence metadata together. A retained original may already exist as an unreferenced inert file, under the existing lifecycle. The caller still owns the observation; an explicit retry of the same ticket/observation is publication-only and cannot fetch. This increment has no owning pending-settlement coordinator object or automatic retry loop. A later adapter must retain exactly those bytes across failed publication, establish quiescence and perform explicit recovery before discarding ownership.

## Bounds and remaining integration

Run JSON is limited to 4 MiB, events to the existing event ceiling, responses to 2 MiB, and each Evidence body to 4 MiB. Before receipt conversion the borrowed observation bounds body, head and candidate metadata, avoiding oversized hashing/copies. Original count is at most 50 and retained Evidence metadata is preflighted at 16 MiB aggregate. Replay reads originals through the existing bounded verified reader, compares full purpose-derived acquisition/text metadata and requires exact whole-record replay. The independent profile limits selected URLs to 50 entries of 2,048 bytes. Complete text that expands beyond the Evidence JSON bound fails publication rather than creating an unreadable record.

These private store calls are synchronous. Reads and transitions can replay up to 50 receipts, verify originals, parse the one content derivative and sync a new original under the caller's workspace lock. This is no responsiveness, wall-time or cooperative-cancellation guarantee. The store preserves a fixed canonical wall deadline, but there is no continuous in-process monotonic deadline across analyst wait yet; a future coordinator must retain the first monotonic segment without treating restart elapsed time as continuity.

Shared extractions are limited to first-deadline arithmetic, budget charging, robots response interpretation, receipt stop precedence, scoped receipt-fact validation and pure Evidence acquisition/promotion construction. Existing v1–v4 wrappers, URL policy, serialization, algorithms and normal callers retain their prior behavior. Ordinary regression checks and historical schema/frozen-file identities accompany the handoff. No benchmark scoring, ranked query/display evidence, access policy certification, native networking or release acceptance is claimed.
