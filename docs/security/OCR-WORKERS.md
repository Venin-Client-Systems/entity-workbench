# Offline OCR foundation

This development adapter runs packaged Tesseract 5.5.2 with the English `tessdata_fast` 4.1.0 model in a disposable native process. It does not use a provider, account, network request, developer runtime, PATH lookup, or first-run download. macOS development confinement remains based on `sandbox-exec`; signed helpers and installed-package verification are separate, unpassed release gates.

## Input and result contract

`Runtime::ocr(scratch_root, raster)` and `ocr_with_cancel(..., &CancellationToken)` accept exactly one canonical PGM raster: `P5\n{width} {height}\n255\n` followed by one byte per pixel. Width and height are 1–8192, at most 12 million pixels total. Rust checks the complete dimensions and payload length before staging or invoking a decoder. Extra images, trailing bytes, comments, non-canonical headers and other encodings are rejected. This is a bounded interchange format for already decoded grayscale images; it is not a general PNG, JPEG, TIFF or PDF importer. The [Netpbm PGM specification](https://netpbm.sourceforge.net/doc/pgm.html) defines the format; our deliberately smaller subset is described above.

The strict versioned `OcrResult` records raster SHA-256, raster byte length, dimensions, job identity, exact engine/model identity, runtime-manifest hash, text and limitations. `raster_sha256` is **not an original evidence digest**. There is no original page mapping, no word regions and no confidence score. A later confined renderer must supply a validated original-to-raster mapping before document citations can be constructed. `ocr::validate_result` is available for eventual canonical acceptance. The adapter does not modify the canonical database or replace evidence text.

Successful recognition yields `recognized`; an empty result yields `no_text_recognized`, which does not prove the image contains no text. Both remain unreviewed and explicitly carry `unreviewed_recognition`, `no_word_regions`, and `no_original_document_mapping`. Oversized, invalid UTF-8/control-bearing output, nonzero worker exits and policy failures are errors, never successful partial claims. The output bound is 512,000 bytes and 128,000 Unicode scalar values. Missing assets or unsupported platform confinement fail closed. Unsupported raster formats fail validation.

The fixed command selects English, the LSTM recognizer, single uniform block segmentation (`--psm 6`) and 300 DPI. It supplies the app-local tessdata directory explicitly. Layout selection is not yet configurable. These flags follow the [Tesseract command-line documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html); the neural OCR recognizer is not a generative-AI dependency.

## Worker permissions and limits

Only the assigned raster can be read, together with the OCR executable, its app-local dylibs/model, minimal OS runtime paths and job scratch. Writes are limited to `result.txt` and private scratch. Java, Lucene indexes, originals and other workspace contents are not granted. Direct networking and process creation are denied; inherited descriptors are closed on exec and the caller environment is cleared except the HOME value required by the observed sandbox launcher. HOME does not grant access to its files. TMPDIR points to job scratch. Thread concurrency is requested as one through `OMP_THREAD_LIMIT`.

The shared supervisor provides cancellation polling, 30 seconds wall/CPU time, descriptor/core limits, final file validation and explicit cleanup. This adapter additionally enforces a 512,000-byte per-file kernel limit. The existing observed tree budget remains a polled bound rather than a hard aggregate disk ceiling; no hard resident-memory ceiling is claimed. A returned `TerminationUnverified` retains the private assignment and prevents publication/confirmed cancellation. Supervisor-crash descendant cleanup remains unverified.

## Build-machine staging

`scripts/stage_ocr_runtime.py --tesseract <existing-binary> --model <existing-eng.traineddata> --destination <fresh-engines/ocr>` stages installed assets without downloads. It currently understands local macOS formula provenance. This build-time workflow does not make Homebrew an installed-application requirement.

The script copies the transitive native dylib closure, rewrites each non-system dependency to `@loader_path` inside the bundle, gives modified Mach-O files ad-hoc development signatures, and rejects unresolved dependencies. Apple documents [loader relocation and run-path dependencies](https://developer.apple.com/library/archive/documentation/DeveloperTools/Conceptual/DynamicLibraries/100-Articles/RunpathDependentLibraries.html). System libraries/frameworks remain OS prerequisites. The resulting bundle is movable; tests copy it to a new path with spaces and execute it under a profile that denies access to its source installation.

`manifest.json` contains exact file byte counts/hashes and platform/model identity. Rust validates the complete bounded runtime tree against the inventory, rejects unlisted/linked/special assets, and hashes every listed file before launching. `NOTICE.json` records source package versions/hashes, source-formula hashes, system dependencies and binary modifications. All available installed package licence/notice files are retained, with pinned Leptonica and English-model licences from `third_party/ocr/`. No model other than English is advertised or copied. The model must hash to `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`. Manifest integrity is not authenticity: release signing, supply-chain review, complete SBOM and licence review remain release responsibilities. These ad-hoc signatures are not distribution signing or notarization.

## Verification and integration limits

`scripts/test_ocr_workers.py` verifies manifest hashes and every Mach-O dependency, relocates the runtime, compiles the synthetic native hostile fixture, and records sanitized evidence under ignored `artifacts/ocr/`. Rejected inventory, build failures and tool timeouts create failed observations with a named phase and replace the latest projection; `scripts/test_ocr_evidence.py` tests that an earlier success cannot survive those failures. It exercises actual English recognition and an empty raster, missing runtime, invalid/oversized inputs, strict result/source binding, forbidden outside/index/input writes and reads, direct loopback networking, forks, environment/descriptor inheritance, live cancellation/reaping and the per-file output ceiling. Hostile attempts use disposable sentinels and a local test listener only.

`fixtures/ocr/synthetic.pgm` is generated from two fictional lines by `scripts/generate_ocr_fixture.swift`. Swift/AppKit are fixture-generation tools only and are not invoked by the application. A two-line successful fixture is not a recognition-quality benchmark.

This slice has no canonical job, review UI, OCR correction workflow, compressed-image decoder, PDF renderer or page citation integration. Intel Mac, Windows, clean offline installation, signed helpers, broad document compatibility and full EW-13 completion remain open.
