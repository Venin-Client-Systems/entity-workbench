# Desktop summary and bounded ledger

This increment implements the consumer migration in [DESKTOP-SUMMARY-CUTOVER.md](DESKTOP-SUMMARY-CUTOVER.md). Native desktop dispatch and the development bridge use the explicit summary response. The default CLI and historical command schemas keep their original shapes. The additive `ew-dev --summary` mode already existed before this UI change.

The interface uses a distinct summary/workspace type. It does not fill omitted transaction or decision arrays with empty arrays. Overview and currency cards use explicit review, duplicate, balance and included/excluded counts; chart positions remain approximate while monetary text remains exact. Finding citations/history and pattern/comparison source reads continue through their dedicated APIs. Account/currency choices reuse the bounded [facet selector](TRANSACTION-FACETS.md).

The envelope's schema version is 1. The retained workspace has its own canonical storage schema version, currently 4; these are different version domains. The transport guard checks the envelope, retained fields and nonnegative consistent denominators. A missing workspace is not treated as a successful backup: backup has a separate explicit response check. Summary publication is monotonic within the current workspace so an older successful response cannot replace a newer imported state. Discarding an obsolete presentation does not retry or reverse its completed mutation. Future workspace switching must explicitly reset this revision guard with workspace identity.

## Ledger scope and provenance

The ledger uses whole-ledger literal search, including the empty query. Draft query/date/account/currency/review/order/page-size controls require **Apply ledger filters**. Changing or clearing a draft does not replace the successful applied scope. Currency pivots from reviewed totals deliberately select that currency and start a fresh page without applying unrelated draft controls. Currency and review selections persist across section navigation; query and date/account drafts restart when leaving the ledger.

The default order is explicitly labelled ascending transaction date. Equal dates retain canonical sequence order in either direction. This changes the old insertion-order presentation and export; it does not change source-order reconciliation. Requests use 25, 50, 100 or 200 rows with the core's existing 2 MiB body limit. A byte-short page advances by its actual returned row count, never by the requested size. The interface shows the complete matching scope, all four review-state counts and the count after review selection. Pending-only scope selected as accepted is not an empty workspace.

First/Back/Next retain at most 100 prior cursors while forward traversal remains available for the entire scope. First restarts it; Back clearly reports when its retained window is shorter than the full visit history. A known revision change resets continuation to the first page of the applied scope. Errors show unavailable state without returning an empty or partial successful page. Query/revision generations discard stale replies, including A → B → A. Each reader lane allows one active command and one latest pending command; replaced pending work is never dispatched. This does not cancel an active Rust read or establish a global processing quota.

Balance annotations are a separate complete ordered read of visible IDs/versions. No retained balance, no prior balance, reconciled, discrepancy and unavailable states remain distinct. An unavailable balance read does not hide transaction rows. The core calculates against canonical source order across review states, independently of page order. Previous-row identity/version and contributor count are preserved in the response. Complete contributor drillthrough remains separate release work.

## Review, counterparts and export

Opening review pins the exact transaction version and originating revision, including handoff from pattern/comparison results. A later workspace refresh preserves reason, correction and counterpart drafts and blocks mutation until the analyst closes and reopens a current verified row. The UI does not apply the latest workspace revision to an older held row. Original amount excerpts still resolve through the separate canonical source reader and show the revision at which they were inspected; source inspection does not adopt a newer mutation revision.

An off-page selection remains open. Structured date/account/currency/review mismatches can be labelled outside the current filters. Otherwise the UI says the row is not on the page and text-query membership is unverified; it does not duplicate Rust's Unicode matcher to infer membership. Close returns focus to the row if present or the stable ledger heading. Compact review retains the existing modal; desktop retains the existing side panel.

Counterpart choices use target/version-bound candidate pages, with 50 rows per request and the same bounded navigation. Defaults remain all accepted rows from other accounts. Unequal amounts, other currencies, matched rows and repeated purchases remain visible. A selected counterpart is retained across page/filter changes at the pinned revision. Canonical matching remains authoritative and may reject a visible candidate. No candidate is implicitly matched or omitted from financial totals.

**Export JSON** reads the complete successful applied scope, not the visible page. Unapplied drafts disable export. It verifies the returned scope echo, revision, matching profile, complete row count, byte length and SHA-256 before download. A changed scope/revision or closed component before download refuses the obsolete export. Only one export is active at a time. The existing native download helper waits for actual completion or an explicit failure; the browser harness separately captures the downloaded file. Source corruption and unavailable exports are errors, not empty files.

## Bounds and design status

Summary still retains evidence text/acquisitions, entities, observations and statement-import ID lists. Rust still builds the canonical view internally before projecting it. Complete export is explicitly in memory with a 256 MiB JSON cap; decoding, integrity checking and native transport add allocations. This work does not claim bounded total memory, indexed performance, a finished 100,000-row application benchmark or the required 16 GB/document/map/graph release benchmark.

The industrial graphite/amber foundation and editable frame references in the [migration plan](DESKTOP-SUMMARY-CUTOVER.md) remain applicable. New ledger/facet/transfer pagination and error-state frames are still unverified. The original unsynced Figma tab remains untouched. Retained browser screenshots and accessibility tests are implementation evidence, not native editable frame creation, remote-save confirmation or design sign-off. Complete release gates remain open.

The final full browser suite passed **104/104**, including 15 new cutover/boundary cases. The production type/build and development core build passed. Desktop Rust tests passed **3/3** and strict desktop Clippy passed using the existing CI resource override; this compiles the new dispatch path but is not packaged-runtime verification. Axe reported zero automated violations for the captured 1440/960 px ledger and compact review, with incomplete manual checks retained.

The first build exposed a discriminated-union TypeScript error, corrected before the real-core run. The first browser attempt rejected every workspace because it incorrectly required storage schema 1 as well as envelope version 1; five failed, one was interrupted and three did not run. The next run passed 6/9: its remaining assumptions were a fixture that did not yet exceed the page byte budget, an amount-cell excerpt expected to contain description markup, and a keyboard assertion made before the new async counterpart read enabled its select. Corrected real fixtures and readiness checks passed 12/12.

The first complete cutover run passed 96/99. Source corruption needed to occur after the new verified page had loaded to continue testing fresh excerpt refusal; two facet tests needed to count the additional independent ledger selectors. Their original integrity and per-lane coalescing assertions remain. A later run was interrupted to add the reviewed balance DTO guard: it retained 39 passes, one failure, one interruption and 62 unrun tests. That failure exposed a pre-existing citation test sampling placeholder roles before metadata resolved. The final 104-case run passed; afterward the citation test was strengthened to wait for resolved metadata, select a known supporting ID and compare stable IDs/roles. Those three cases passed again, and a four-case focus/visual follow-up passed against unchanged production code.

The new checks include real traversal past 100 prior pages, actual byte-short pages without weakened limits, full 251-row export beyond its visible page, independent failed balance reads and retry, complete export refusal after original corruption or applied-scope change, empty versus unavailable reads, explicit backup confirmation, off-page stale review preservation, broad 62-row counterpart paging, coalesced late replies and monotonic publication of actual old/new core summaries. Negative DTO guards operate on copies of real canonical results; no successful network response is fabricated.
