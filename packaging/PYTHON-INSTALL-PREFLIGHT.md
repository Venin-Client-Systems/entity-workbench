# Python install-layout and native-loader static preflight

This EW-07/#11 record inspects the already reviewed CPython 3.13.15 macOS arm64
tree and 58 locked wheel archives. It proposes an installation contract; it does
not install packages, execute the staged interpreter, activate workers or pass a
release gate. The [source-bound receipt](evidence/python-static-preflight-2026-09-25.json)
retains all native identities, loader edges, hook metadata and inspection-tool
identities. `static_inspection_complete` means this static inspection finished,
not that native loading or package imports passed.

## Proposed logical installation contract

| Input | Proposed bundle-relative destination |
| --- | --- |
| Ordinary wheel member | `install/lib/python3.13/site-packages/<member>` |
| The single spread member `igraph-1.0.0.data/headers/igraphmodule_api.h` | `install/include/python3.13/igraph/igraphmodule_api.h` |
| Existing CPython files and materialized aliases | Their unchanged manifest paths |
| Root and vendored `.dist-info`, licence files and package data | Their unchanged relative locations beneath site-packages |
| Console/GUI wrappers | None generated by this preflight |

These rules yield **11,037 proposed ordinary file locations**, with no observed
cross-wheel, wheel/runtime, NFC/casefold or file-as-parent collisions. There is
no observed site-packages shadow of `site.py`, `sitecustomize.py` or
`usercustomize.py`. The only wheel `.data` member is the 2,220-byte igraph header;
there are no `.data/scripts` members. The header placement agrees with the
retained upstream pip non-venv scheme: `_internal/locations/_sysconfig.py` joins
the interpreter include directory with the distribution name. The receipt pins
that source and CPython's `PYTHON.json` layout metadata; no interpreter was
executed to discover a scheme.

A future installer must preserve source-to-destination attribution, copied
hashes, every notice and the primary distribution identities. It must produce
a newly verified inventory and truthful installed `RECORD` metadata after any
relocation or generated file. This preflight's full mapping hash and rule table
are not an installer or an installed `RECORD` claim. The 105 recognized wheel
notice files remain within their original archives, and the complete archives
also retain material not recognized by notice filenames. Legal completeness is
unverified; the CPython metadata's missing `LICENSE.zlib-ng.txt` reference is
still unresolved.

## Native-library findings

System `lipo` and `otool` inspected **188 unique Mach-O files across 196 logical
locations**. Every inspected image contains an arm64 slice. Only that slice's
load commands were analyzed; other slices and other target platforms remain
unverified. The scanner copied 260,717,528 bytes into fresh numeric files with
mode `0600` and did not execute any copied image.

The receipt classifies **all 588 logical load-command edges**:

| Classification | Count | Meaning |
| --- | ---: | --- |
| Local | 235 | Exactly one native logical location under the proposed tree resolves the recorded reference |
| OS library | 353 | An absolute `/usr/lib/` or `/System/Library/` install name; not opened or compatibility-tested |
| Unresolved / ambiguous | 0 / 0 | None observed within this limited static resolution model |

All **26 distinct OS install names**, including the one weak
UniformTypeIdentifiers reference, appear in the receipt. The model uses each
image's own `LC_RPATH` and the fixed `install/bin/python3.13` executable's
`LC_RPATH`, with no environment-derived or additional inherited loader state.
It does not emulate dyld's complete load order. There are 54 logical RPATH
records. No required non-system absolute load path is observed.

NumPy's four `/DLC/numpy/.dylibs/...` `LC_ID_DYLIB` strings are **library
identities**, not incoming dependency paths. Incoming references to those
libraries resolve through local `@loader_path` spellings. This record does not
misclassify those identity strings as missing files or propose rewriting them.

This is not proof of actual dyld loading, `dlopen`/`ctypes` calls, package imports,
plugin behavior, resources, signatures/notarization, confinement or macOS
compatibility. OS paths identify dependencies on ordinary system facilities;
their availability on a supported minimum OS has not been established. No
minimum macOS version, Windows support or Intel Mac support is inferred.

## Reproduce the static inspection

Use an existing macOS development host with Python 3.13 or later and installed
Apple `lipo`/`otool`. Supply only the exact previously staged runtime and original
wheel input directory. The destination parent must exist and the destination
must be fresh. It is an exclusively controlled development workspace, not a
sandbox against another process running as the same user.

```sh
python3 scripts/inspect_python_native_layout.py \
  --runtime /path/to/verified-cpython-tree \
  --wheelhouse /path/to/reviewed-wheel-inputs \
  --output artifacts/python-static-preflight
python3 -m unittest discover -s scripts/tests -p test_python_native_preflight.py -v
python3 -O -m unittest discover -s scripts/tests -p test_python_native_preflight.py -v
```

The inspector reuses no-follow, single-link input handling and full tree/hash
verification. It checks wheel digests before and after bounded ZIP inspection,
reads members to EOF for CRC/size validation, rejects unknown spread paths and
retains complete case-sensitive entry-point declarations. Limits are 80 MiB per
inspected file, 512 MiB total wheel expansion, 512 MiB unique native scratch,
20,000 members per wheel, and ten seconds per static tool invocation. Tool output
is file-backed and rejected above 2 MiB (512 bytes for architecture output);
only fixed parsed fields enter the public report. There is no network client,
pip, uv, package-code import or candidate-interpreter invocation.

Failure returns a generic sanitized error and retains the initial incomplete
receipt and any owned scratch for review. A timeout or interruption cannot leave
a previous successful report because output directories are never reused.
The actual source-bound observation is not clean-commit release evidence.

The next implementation requires a separately reviewed finite installer,
installation/inventory checks and actual isolated-prefix tests. Those must cover
the fixed bootstrap, required plugin discovery, no unintended user/site paths,
offline imports and analytical fixtures, runtime-computed native loads, signed
relocation and worker confinement. No such execution was authorized or performed
in this slice.
